Understand the four test functions

These are benchmark loss functions, not learning algorithms. We use them to test how well optimizers such as SGD, Momentum, and Adam search for low values. Each surface has a different challenge, so comparing them helps us understand where an optimizer works well and where it may struggle.

1. Rosenbrock Valley

What it is: A smooth function with a long, narrow, curved valley. Its global minimum is at (1, 1), where the loss is 0.

How it behaves: The optimizer must follow the bend in the valley. The steep sides and gentle direction along the valley can make progress slow or cause zig-zagging.

When we use it: To test whether an optimizer can navigate narrow curved valleys and converge accurately instead of overshooting or moving slowly.

In simple words: Imagine walking down a winding, narrow valley. The challenge is to follow the curve all the way to the bottom.

f(x,y) = (1 − x)² + 100(y − x²)²

2. Himmelblau’s Function

What it is: A two-dimensional function with four different global minimum points, each having a loss of 0.

How it behaves: The starting position can influence which minimum an optimizer reaches. Different runs can end in different valleys, even when each reaches a good solution.

When we use it: To compare how optimizers explore a landscape with multiple good solutions and to observe how the starting point affects the result.

In simple words: Picture a landscape with four equally deep valleys. Where you start can determine which valley you reach.

f(x,y) = (x² + y − 11)² + (x + y² − 7)²

3. Rastrigin Function

What it is: A highly bumpy, repeating function with many local minima. Its global minimum is at (0, 0), where the loss is 0.

How it behaves: The many small valleys can attract an optimizer before it finds the deepest one. An optimizer may settle at a local minimum rather than the global minimum.

When we use it: To test an optimizer’s ability to explore the search space and avoid getting trapped in local minima.

In simple words: Imagine searching for the deepest dip in a field full of small dips and bumps.

f(x,y) = 20 + x² + y² − 10[cos(2πx) + cos(2πy)]

4. Ackley Function

What it is: A benchmark function with a broad outer region and a rippled landscape surrounding its global minimum at (0, 0), where the loss is 0.

How it behaves: The relatively flat outer area can provide weak directional information, while the ripples create smaller variations that can complicate the search.

When we use it: To compare how well optimizers move across flat regions, handle local variations, and converge toward the global minimum.

In simple words: Think of walking over a broad, almost flat area with ripples, trying to reach the lowest point in the center.

f(x,y) = −20e−0.2√(0.5(x²+y²)) − e0.5(cos(2πx)+cos(2πy)) + e + 20
How to use this section: Choose a surface in the experiment controls, then watch SGD, Momentum, and Adam move across it. Compare their paths and loss values. The best result depends on the surface, starting point, and learning rate.

How the optimizer works

Every iteration repeats the same basic idea: measure the slope, move downhill, repeat.

Step 01

Calculate loss

Evaluate the current point on the chosen loss function.

Step 02

Calculate gradient

Estimate which direction goes uphill using partial derivatives.

Step 03

Update position

Move in the opposite direction, scaled by the learning rate.

Step 04

Repeat

Keep updating until the optimizer reaches a low-loss region or the experiment ends.

Core idea: θnew = θold − learning rate × gradient. Momentum adds a velocity-like memory, while Adam adapts the step using running statistics of gradients.

Project presentation

This is an educational visualization project. It is useful for explaining why optimization matters when training machine-learning models: model parameters are adjusted repeatedly to reduce a loss function.

Problem

Optimization concepts are abstract when shown only as formulas or logs.

Solution

An interactive 3D lab makes the loss surface and optimizer trajectories visible.

Technology

HTML, CSS, JavaScript, and Three.js. No backend is required for this demo.
